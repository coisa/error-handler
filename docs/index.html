PHP 8.3+ · PSR integrations

CoiSA Error Handler

Compose private diagnostic reporting, owned PHP callbacks and explicit HTTP response rendering.

The library supplies handlers and PSR adapters. Applications choose diagnostic sinks, PSR implementations, callback installation and response emission.

Match documentation to your installed package version. For an upgrade from 2.x, follow the migration guide and compare the 2.x API documentation.

Start with installation and direct reporting, then select process callbacks or HTTP composition. Add application services through the Interop provider.

Installation and setup

composer require coisa/error-handler

Use Composer 2 to install the library on the actual PHP runtime. The declared PHP constraint is ^8.3; the CI matrix targets PHP 8.3–8.5. FastForward Container ^1.10 and the Interop provider contract are runtime dependencies.

Applications supply loggers, dispatchers, PSR-17 implementations and their emitter as needed. The development checkout supplies Nyholm and Phly for its synthetic recipes; optional filp/whoops:^2.18.4 is needed only where development HTML is selected.

Read example setup for the selected autoloader and verifier dependencies. Resolve with the actual PHP runtime and retain application lockfiles. Consult the recorded test evidence; a permitted constraint is not proof that every combination is clean.

The cookbook below runs from a matching source checkout: Composer archives omit the top-level examples/ directory. Keep its bootstrap and assertion helper beside the recipes. Installed applications can instead run the bundled application programs with their explicit Composer autoloader.

Start with direct reporting

A reporter implements ThrowableHandlerInterface::handleThrowable(): void. The core delegates to it without installing PHP callbacks. A direct call returns when the reporter returns; collaborator failures propagate.

Run php examples/reporters.php after setup. The synthetic program records its two ordered deliveries and prints them. Replace those recording callbacks with private application sinks. No container or native registration is needed for direct construction.

Report directly to an application logger

The retained LogThrowableHandler adapter takes an application PSR-3 logger, an optional level (ERROR by default) and context.

Each call logs the exact message, including empty, with the original throwable under exception over a caller value. Other context retains its types and identity. Logger failures propagate unchanged; the adapter adds no retry, output or registration.

A logger service alone does not attach this reporter. Compose it explicitly or use a required reporting-interface binding through the merged-provider override.

Choose the process lifetime

For uncaught process failures, register at bootstrap and leave the handler active through termination. For a caught operation, restore its callbacks in finally. An unwinding finally runs before PHP's uncaught-exception callback, so unregistering there returns responsibility to the previous handler.

Callbacks are process-wide. Use distinct nested handlers and unregister in reverse order; out-of-order removal raises LogicException. Stable callback identities and one retained shutdown callback per instance avoid adding another shutdown callback on each registration cycle. Only the active owner handles shutdown; PHP retains queued callbacks until process exit.

A successfully reported globally uncaught throwable exits 1. Direct reporting does not terminate. Native fatal errors remain fatal, and a fatal that aborts PHP's shutdown queue cannot be recovered by adding handlers. See the lifecycle contract and CLI source.

Supply PHP-error policy explicitly

CallablePhpErrorHandler($callback) passes code, message, filename and line unchanged. Inject its interface instance as the second core argument. The callback owns mask/conversion policy:

All three core constructor inputs accept their matching interface or a callable. Existing interface objects retain identity and take precedence over __invoke(). The reporter is required; omitted or null PHP-error and shutdown inputs keep their defaults. Construction invokes no callback and installs nothing.

The void interface ignores false/null callback results; they do not restore native PHP fall-through. There is no fifth error-context argument. A custom PHP callback owns suppression/conversion; the default adapter honors suppression. The complete PHP-error recipe supplies all three callbacks and pairs active shutdown notification with cleanup.

Select diagnostic branches explicitly

FilteringThrowableHandler($reporter, $predicate) evaluates a required boolean predicate once. True forwards the same throwable once; false skips only that delegate. Predicate/delegate failures propagate, and non-boolean results raise TypeError.

This explicit decorator adds no output, registration or automatic aggregate membership. A nonmatch is not recovery and does not select an HTTP body. Rendering remains a separate boundary after the middleware's reporting call.

Attempt every reporter and retain every failure

BestEffortThrowableHandlerAggregate attempts its fixed reporter slots in order with the same original. Any failure produces one AggregateReportingException after all attempts; zero/all-success passes return normally.

The original and ordered failure objects remain private diagnostics. The fixed summary is not a public redaction guarantee. This adapter does not change the default fail-fast aggregate or create an HTTP fallback: its reporting failure propagates before middleware rendering. Applications own terminal handling and durable delivery.

Use the required Interop provider

ErrorHandlerServiceProvider implements the Interop provider contract and reuses FastForward factories/autowiring. This bootstrap adds application dependencies and optional reporters:

FastForward caches services. The base reporting alias selects a fail-fast aggregate, silent when no optional reporter is available. Explicit Log, Filtering, Callable PHP-error and BestEffort adapters are not discovered merely by registering their concrete classes.

For a required reporter, renderer or other replacement, merge library maps with application definitions last in one AggregateServiceProvider, as below. Separate providers use first-success resolution and can fall back on PSR construction errors; their short bootstrap is not a required-override guarantee.

Legacy ErrorHandlerContainer, ConfigProvider, Laminas discovery and old container factories are removed. Follow the provider guide and migration map. Core handlers remain independently constructible.

Select a pure response profile

Each representation provider returns only its own map; the application composes it with the base provider and required private reporter/PSR-17 bindings. JSON declares two entries: its configured pure renderer and response-interface alias.

The default JSON profile is public. Its optional constructor bool is selected from trusted configuration before container construction. Pass a real boolean; casting the string "false" enables PHP truthiness. The major middleware supplies the private report before pure rendering.

The Whoops profile has no constructor and only three entries: a lazy PrettyPageHandler via InvokableFactory, a pure renderer via lazy CallableFactory, and its response alias. Install optional filp/whoops:^2.18.4 where HTML is selected. Configure a page before container lookup and bind it through ServiceFactory when required.

A configured page is cached and can be reused sequentially: configuration stays, current diagnostic data replaces the previous data, and the page retains its latest diagnostic. Each render still uses a fresh unregistered Run, response and body. Concrete page-factory failures can trigger FastForward autowiring fallback even inside an aggregate; binding order is not universal failure propagation or concurrent isolation.

Invoke this factory for distinct handlers and middleware in independent nested scopes. Repeated middleware get() calls remain cached; the process handler stays separate. Lookup and construction install no callbacks. Read provider maps, required overrides and failure limits.

Report once, then render explicitly

Middleware requires one scoped object implementing both lifecycle and throwable reporting. It registers, calls downstream, reports a caught throwable, invokes a pure response renderer and unregisters in finally. Reporter failure prevents rendering; renderer failures propagate after callback restoration. Successful downstream responses pass through unchanged.

The base provider's GenericThrowableStreamFactory returns Internal Server Error independently of reporter output. Integer error codes 400–599 are preserved, other integers/string codes use 500, and PSR-17 supplies reason phrases. Keep diagnostics private: an echoed reporter can still corrupt emission outside the returned response.

The retained pure JSON factory returns application/json with {"error":"Request failed"}. Explicit debug adds class/message/file/line and trace metadata without arguments/objects, substitutes invalid UTF-8 and sets Cache-Control: no-store. Messages and paths can still expose secrets. No client header or environment name enables debug automatically.

The trusted application choice made earlier in this recipe selects JSON or optional WhoopsThrowableResponseFactory. Its manual third argument remains callable(): PrettyPageHandler. It returns text/html; charset=UTF-8 and no-store without emission, native headers, registration or controlled quit. Whoops source/globals/traces are development disclosures; selected key hiding is not comprehensive redaction.

ReportingThrowableResponseFactory remains an explicit utility for other pipelines that still need reporting. Neither the base provider nor these profiles select it after the middleware has already reported. Request/Accept negotiation is application policy; these providers select explicit renderers. The native Whoops STDIN source-read limit is also separate: its warning is another event, not a second delivery of the original.

Use output capture only for a separate public renderer

This explicit stream adapter captures deliberately public output; it must not invoke the private reporter again. Empty output uses the generic body and "0" is preserved. Cleanup removes reachable removable scopes, stops without progress/protected buffers and preserves a primary renderer failure. Native exit/fatal effects remain unrecoverable. The application owns response emission and terminal policy; see HTTP boundaries.
